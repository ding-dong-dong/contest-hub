## 1. 新增字段（snake_case，前端 adapter 映射驼峰）

| 字段 | 类型 | 空值约定 | 说明 |
|------|------|----------|------|
| `major_limit` | string | 永不空（"不限专业"/"待确认"/官方原文） | 官方参赛专业限制原文，**禁止当推荐专业用** |
| `recommended_majors` | string[] | `[]` | 推荐专业，10 枚举数组；无依据是 `[]` 不是字符串、不是 null |
| `recommended_major_reason` | string \| null | `null` | 30-150 字推荐依据（赛道/任务/材料/评审标准） |

10 个枚举值（顺序可用于筛选下拉）：

OpenAPI 位置：`components.schemas.ContestOut.properties`（array + items.enum；reason 可空 maxLength 150）。

## 2. 后端推荐规则落地（与清单第 3-4 节一致）

1. **硬过滤只看 major_limit**：明确不符合才排除；"不限专业"/含"包括但不限于"/只谈学历院校身份（如师范生）
   一律不按专业排除；"待确认"保留并在 warnings 给"参赛专业限制待确认"，`qualification_pending=true`。
2. **recommended_majors 只加分不排除**：
   - 用户专业命中推荐专业：专业项 20/20（完全匹配）
   - 相关/官方不限：12/20；资格待确认：8/20；兴趣另算 0-10（专业与兴趣合计仍为 30 分）
   - 分值是清单第 4 节"待定"的暂定值，田淋元定稿后只改 `app/recommend.py::_major_interest_score`。
3. 推荐专业为空：warnings 增加"推荐专业待确认（不影响报名…）"，不报错、不排除。
4. 已截止/取消：不进 `/contests/recommend`（硬过滤#1），但 `/contests` 列表与筛选仍可见。

## 3. 接口行为

- `GET /contests?major=医学`：筛选**不做硬删除**——资格开放/命中/待确认，或推荐专业含该专业的都返回；
  明确专业不符的隐藏。实测医学返回 28 条（含已截止的 imp_016/017）。
- `GET /contests/recommend`：入参不变（grade/major/interests/experience/time_per_week/school）；
  每个 item 的 `contest` 已带完整新字段，前端无需二次请求；`scores` 五项键名与总分口径未变。
- 写接口（POST/PUT）仍需 `X-Admin-Key`（Render 环境变量），支持直接传推荐专业数组，
  也兼容 `"计算机、设计"` 字符串（后端自动拆分校验，非法枚举项剔除而非报错）。

## 4. 前端联调要点（对应清单第 8 节）

1. 卡片标签：`推荐专业：${recommended_majors.join('、')}`；空数组显示"推荐专业待确认"。
2. 详情页：参赛限制显示 `major_limit` 原文；推荐依据显示 reason，null 时不渲染该区块。
3. 筛选下拉用上面 10 枚举；辅助文案：**"推荐专业用于帮助优先选择，不代表其他专业不能报名。"**
4. 旧接口兼容：两字段永远存在（数组/null），无需版本判断；注意 375px 与桌面无横向溢出。
